# v0.4.0 — Secure Plugin Manager & Official Registry

> History. The administrative tool named here (`ModularRuntime.Publisher`) has been maintained in a
> separate private repository since the publishing split; this repository keeps the formats and all
> verification ([REPOSITORY_ORGANIZATION.md](REPOSITORY_ORGANIZATION.md)).

v0.4 adds plugin installation, verification, update, and removal to the daemon, an
authenticated official registry, a team-only publishing tool, and the matching GUI and CLI.

## Components

```text
                GitHub official registry (team only)
                registry.json + registry.sig + packages/*.zip
                              │  https (or a local mirror directory)
                              ▼
 ModularRuntime.Daemon ── PackageManager (operations, uploads, policy)
                              │
          ┌───────────────────┼─────────────────────┐
   ModularRuntime.Registry   ModularRuntime.Packaging            ModularRuntime.Loader
   (catalog, signature,      (ZIP inspection, paths, hashes,     (manifest reader, factories,
    rollback, cache,          signatures, trust store,            IPluginLoadVerifier gate,
    downloads)                staging, atomic store, recovery,    register/unregister)
                              PackageLoadVerifier)                       │
                                                                 ModularRuntime.Engine
                                                                 (UnregisterAsync)

 ModularRuntime.Desktop / ModularRuntime.Cli ── IPC (packages.*, registry.*) ── Daemon
 ModularRuntime.Publisher (team tool, not shipped) ── uses Packaging + Registry
```

| Project | Role |
| --- | --- |
| `ModularRuntime.Packaging` | Package format and verification, trust store, deterministic builder, installation store (staging, journal, records, recovery), load verifier |
| `ModularRuntime.Registry` | Registry model and validation, authenticated refresh, rollback state, cache, download transport (https, file mirrors) |
| `ModularRuntime.Publisher` | Team-only CLI: keygen (test/dev), prepare, sign with approval, pack, verify, registry build/sign/verify |
| `ModularRuntime.Daemon` | `PackageManager`: tracked operations, uploads, stop/unregister/swap/register, auto-start policy |
| `ModularRuntime.Loader` | `IPluginLoadVerifier` hook before every load; `RegisterInstallationAsync`, `UnregisterAsync`, `WaitForUnloadAsync`; optional `author`/`description` in `plugin.json` |
| `ModularRuntime.Engine` | `UnregisterAsync` for inactive plugins (validated, stopped, failed) |

The GUI never extracts, verifies, or loads packages; the package manager has no dependency on
WPF.

## Profile layout

```text
<profile>/
  plugins/<plugin-id>/            installations (managed) and hand-copied folders (unmanaged)
  plugins/.staging/<operation>/   daemon-owned staging (same volume as plugins/, so moves are atomic)
  packages/installed/<plugin-id>/ record.json, integrity.json (exact bytes), integrity.sig (official)
  packages/registry/              cached registry.json + registry.sig, state.json (highest revision)
```

## Operations

| Operation | What the daemon does |
| --- | --- |
| Install official | Find the entry in the verified catalog → compatibility → download (size-limited) into staging → verify (hash from catalog, signature, every file) → publish atomically → register (not started) |
| Install local ZIP | Client uploads the file in chunks to staging → *inspect* verifies it and returns a preview → *install* (unsigned packages need `acceptUnverified`) → publish → register |
| Verify | Signature (official) and every file's size and SHA-256 against the recorded manifest; loads nothing |
| Update | New package verified first; then (only with `stopIfRunning` if running) stop → unregister → wait for unload → swap → register; any failure re-registers the previous installation unchanged |
| Remove | Same take-out sequence, then atomic removal of the installation and record |
| Check updates | Installed managed packages vs. the highest version in the cached catalog |

Operations run in the background with an ID, stage (`Queued`, `Downloading`, `Verifying`,
`Stopping`, `Installing`, `Removing`, `Completed`, `Failed`, `Canceled`), progress, and result,
broadcast as `packages.operation` notifications. One operation per plugin at a time
(`operation_in_progress`), at most two running concurrently. Cancellation is honored until the
swap starts; the swap itself always completes or rolls back.

Nothing is ever started automatically after installation or update. `--auto-start` never
starts local packages without an official signature.

## Desktop

> The catalog, updates and *Install from ZIP* later moved to a separate **Store** page; the
> Plugins page now manages installed plugins only. See [STORE_AND_RESTART.md](STORE_AND_RESTART.md).

The Plugins page had three areas and an **Install from ZIP** button:

- **Installed** — every plugin with state and a trust badge (Official verified, Official (test
  key), Local unverified, Modified, Verification failed, Unmanaged), start/stop, details with
  source, signing key, package SHA-256, file count, last verification and its problems, and
  *Verify integrity*, *Update to X*, *Remove…* (confirmed; running plugins are stopped only
  after confirmation).
- **Explore** — the authenticated catalog (revision, signing key, expiry, a warning when test
  keys are trusted), search, category filter, details (author, compatibility, source, release
  notes), *Install*, *Refresh catalog*. The first visit downloads and verifies the catalog when
  none is cached.
- **Updates** — newer versions with release notes; *Update* asks for confirmation.
- **Install from ZIP** — file picker → upload to the daemon → the daemon's verification shown
  in a preview (name, ID, version, author, origin, signature, integrity, compatibility). For an
  unsigned package a warning explains that hashes inside a package prove nothing about its
  origin, and *Install* stays disabled until the user ticks the acknowledgement. Replacing a
  running version requires ticking "Stop the running version".

Operation progress comes from the daemon and survives reconnection (operations are listed
again on reconnect). Success is shown only when the daemon reports completion. Every page state
(loading, empty, error, disconnected) and both themes are supported.

## CLI

```text
registry status | refresh | list | info <id>
plugins packages | updates | verify <id>
plugins install <id> [--version <v>]
plugins install-zip <file.zip> [--allow-unverified] [--stop-if-running]
plugins update <id> [--stop-if-running]
plugins remove <id> [--stop-if-running] [--yes]
```

`--json` works for all of them. Unsigned ZIPs need a typed confirmation interactively, or
`--allow-unverified` in scripts (structural validation still applies). Exit codes: 0 success,
1 the operation ran and failed (verification, download, …), 2 usage, 3 daemon unavailable,
4 the daemon rejected the request (for example `plugin_running`, `unverified_not_accepted`,
`registry_rollback`).

## Daemon options

`--registry <https url | directory>` (or `registryLocation` in `config/daemon.json`) and, for
development only, `--test-trust-store <file>`. See [OFFICIAL_REGISTRY.md](OFFICIAL_REGISTRY.md).

## Limitations

- No sandbox; plugins run in-process with the user's permissions ([PLUGIN_SECURITY_MODEL.md](PLUGIN_SECURITY_MODEL.md)).
- No production key and no default registry location exist yet; both are set by the administrator before release.
- No online revocation; revocation ships with product updates.
- Replay of an older unexpired catalog is possible on new or offline profiles (bounded by `expiresAt`).
- ~~A stopped plugin cannot be started again without re-registration.~~ Resolved: see [STORE_AND_RESTART.md](STORE_AND_RESTART.md).
- After stop, assembly files may stay locked until the load context is collected; updates and removals wait up to 15 s and fail safely (`files_in_use`) otherwise.
- Hand-copied (unmanaged) plugins are still loaded without verification.
- No automatic updates, no dependency resolution between plugins, no package feed other than the registry.
