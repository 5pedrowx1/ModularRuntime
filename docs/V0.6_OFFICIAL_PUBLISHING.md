# ModularRuntime v0.6.0 — Official Publishing Infrastructure

Official plugins are now reviewed, rebuilt in a controlled environment, approved, and signed by
the ModularRuntime administrator, and can be withdrawn or revoked. Product version **0.6.0**;
plugin API unchanged, **0.3** ([VERSIONING.md](VERSIONING.md)).

The administrator's review, build, approval, and signing tools are maintained in a separate,
private repository that depends on this one. This repository contains everything needed to
develop, package, submit, install, and **verify** plugins.

## What changed for users and plugin authors

| Area | What |
|---|---|
| Registry | catalog schema 2: `status` (published/withdrawn/revoked), `statusReason`, `statusChangedAt`, `advisoryUrl`, `buildId`, `approvalSha256`, `revokedKeys`; the last verified catalog stays the revocation source offline |
| Registry | `RegistryCatalogCheck`: the public publication rules (signature, validity, rollback, immutable versions, kept revocations, package files, supported API) |
| Daemon | `RevocationGate` before the integrity check; revocation and withdrawal rules for install, update, and local ZIP; warnings for running plugins; `Revoked` trust state |
| CLI | `REVOKED` and status in `plugins packages`, `registry list/info` |
| Desktop | Store details: status, reason/advisory, publication (build, commit), version history; Install disabled for revoked/withdrawn/bad-key versions; Plugins page revocation warning |
| DevTools | `prepare-submission --license --source-repository --source-commit`, submission schema 2, lock files; `registry-check` |
| Submissions | `ModularRuntime.Submissions`: the public submission format and the secret classifier shared with the official validator |
| Packaging | key purpose `approvals` (never trusted by the daemon) |
| Template | `RestorePackagesWithLockFile` |

## Limitations

- No production key, no official catalog URL, and no registry repository exist yet.
- Reviews and automated checks reduce risk; they cannot prove a plugin is safe. A signature
  establishes origin and integrity.
- v0.4/v0.5 daemons cannot read schema 2 catalogs (they reject them, which is fail-safe).
- Revocation reaches a daemon only when it refreshes; running plugins are not stopped automatically.
